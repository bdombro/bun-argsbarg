## 1. ⬜ Support current MCP without breaking existing clients

[src/mcp/server.ts](../../src/mcp/server.ts) only advertises `2025-06-18` and `2024-11-05`. The published specification now points to `2026-07-28`; this is not a version-constant update.

- Add modern discovery and per-request version/capability handling, required result/cache metadata, and appropriate version errors. Preserve existing initialization-based clients; assess `2025-11-25` compatibility separately rather than claiming it implicitly.
- Modern MCP removes `initialize` and server-initiated JSON-RPC requests. Client input uses multi round-trip requests (MRTR). Do not build a new public session/request API around the older model; expose request-scoped elicitation when needed.
- Roots, sampling, and protocol logging are deprecated in the modern revision. Keep the current one-time cwd convention on supported legacy sessions only. Modern calls must not inherit another request's workspace through process-global cwd; use explicit directory inputs or subprocess cwd instead.
- Verify discovery, direct modern calls without initialization, missing/unsupported metadata, required result fields, and legacy fallback. Exercise input-required retries without repeating side effects, and unrelated workspaces sharing a process without cwd leakage.

## 2. ⬜ Validate JSON-RPC envelopes and lifecycle

[src/mcp/server.ts](../../src/mcp/server.ts) silently drops malformed JSON and non-object messages. Its TypeScript cast does not validate IDs, methods, or params; normal methods can execute without initialization, and repeated initialization can change negotiated state.

- Return protocol-appropriate parse, invalid-request, and invalid-params errors instead of leaving callers waiting. Validate IDs, envelope variants, parameter shapes, and mutually exclusive result/error fields before dispatch.
- Preserve notification silence, numeric/string ID identity, immediate client-response routing for legacy sessions, and serialized application execution. Apply initialization rules only to legacy traffic, not modern requests.
- Verify malformed input, null/fractional/object IDs, invalid methods/params, missing IDs, duplicate initialization, and valid traffic after each recoverable error. Update existing tests that intentionally skip the handshake.

## 3. ⬜ Make structured results match their wire schemas

[src/mcp/result.ts](../../src/mcp/result.ts) turns strings into `{ content, contentType }`, while [src/headless/tool-call.ts](../../src/headless/tool-call.ts) then nests that object under `result` for a declared string output schema. The advertised schema instead expects a string. Arrays without an output schema can also escape as bare `structuredContent`, although the supported `2025-06-18` revision requires an object.

- Make the advertised schema, success payload, and JSON text fallback agree for objects, arrays, strings, and binary bodies. Keep legacy object-root requirements separate from modern JSON-value support.
- Reconcile the current no-runtime-output-validation policy with MCP's requirement that successful structured results conform to advertised schemas. A malformed handler result must not be presented as schema-conforming success.
- Verify actual wire responses against their listed schemas, including scalar/array wrappers and `ctx.respond()`. Preserve tool-execution errors as `isError: true` and avoid unrelated HTTP behavior changes.

## 4. ⬜ Support cancellation and progress during tools

[src/mcp/server.ts](../../src/mcp/server.ts) queues all notifications behind the active tool and ignores cancellation. [src/core/types.ts](../../src/core/types.ts) exposes neither a cancellation signal nor a progress reporter to handlers. A stopped client request can leave child CLIs running and block later tools.

- Handle cancellation outside the application queue, matching the original wire ID. Skip cancelled queued work and expose cooperative cancellation for active handlers and their subprocesses; do not overlap tools while stdout capture is active.
- Expose request-scoped progress using the supplied progress token and the stable transport writer. Stop notifications on completion/cancellation; ignore unknown or completed IDs. Do not promise to interrupt synchronous code or uncooperative child processes.
- Verify cancellation while queued and running, child cleanup, completion races, progress during output capture, and subsequent tool execution. Keep transport-specific cancellation semantics version-aware.

## 5. ⬜ Expose standard tool annotations

`McpToolConfig` in [src/core/types.ts](../../src/core/types.ts) only supports visibility, description, and notes. [src/mcp/tools.ts](../../src/mcp/tools.ts) and `tools/list` cannot expose read-only, destructive, idempotent, or open-world hints. Hosts cannot distinguish inspection from mutation through standard metadata.

- Allow explicit standard annotations per tool, including the built-in resource reader. Use conservative defaults; do not infer safety from command names or the presence of `--yes`.
- Verify `tools/list` metadata and unchanged invocation behavior. Document that hints are advisory, not authorization or a replacement for host confirmation.

## 6. ⬜ Return native MCP content blocks

[src/mcp/result.ts](../../src/mcp/result.ts) only emits text blocks. Images/audio become base64 data inside structured JSON, and handlers cannot return native resource links or embedded resources for clients to render or consume directly.

- Provide an explicit, typed way to return native MCP content while preserving ordinary CLI/HTTP responses. Support image/audio MIME types and resource content without guessing from arbitrary JSON keys.
- Verify native blocks, binary fidelity, mixed text/media, error results, and fallbacks for supported protocol versions. Retain the current JSON result path for existing consumers.

## 7. ⬜ Add Streamable HTTP MCP

MCP is stdio-only. [src/http/server.ts](../../src/http/server.ts) serves REST/OpenAPI, not an MCP endpoint. URL-only or remote hosts cannot use argsbarg's MCP server directly. This is an optional expansion, not a stdio conformance failure.

- Add an opt-in MCP endpoint separate from existing REST routes, sharing protocol behavior without sharing mutable client state. Follow the selected protocol revision's HTTP and cancellation rules rather than copying obsolete SSE/session behavior.
- Include origin validation, local-only defaults, authentication/authorization integration, and isolation between callers. Process-global cwd or output capture must not leak between clients.
- Verify a real Streamable HTTP client, request-scoped notifications, cancellation, invalid origin/auth rejection, and unchanged stdio/REST behavior. Do not expose a remote endpoint without these protections.

## Not Planned

Prompts, resource templates/subscriptions, pagination for small static catalogs, tasks, and MCP Apps are optional expansions, not blockers for the current CLI-to-tools use case. No roots cache/refresh, new lifecycle hooks, or public legacy roots/sampling API.
