## 1. ✅ Add MCP 2025-11-25 compatibly

[src/mcp/server.ts](../../src/mcp/server.ts) negotiates `2025-11-25`, `2025-06-18`, and `2024-11-05`. Unsupported requested revisions are offered the newest supported version. Initialization, ping, session capabilities, and older clients' text-only results remain supported.

- Preserve the private once-per-session roots/list request and five-second fallback. Exactly one usable local root selects cwd before hooks and children; hooks and explicit child cwd can override it.
- Keep input reading independent of serialized application calls. No roots cache/refresh, public session API, new hooks, settings, or CLI/REST changes.
- Regression checks cover negotiation, old-client schemas/results, roots selection, unsupported/unusable roots, timeout, disconnect, hooks, and queued calls.

## 2. ✅ Validate JSON-RPC envelopes and lifecycle

[src/mcp/server.ts](../../src/mcp/server.ts) now validates envelopes, IDs, methods, params, and optional progress metadata instead of silently dropping malformed requests.

- Return protocol-appropriate parse, invalid-request, and invalid-params errors instead of leaving callers waiting. Validate IDs, envelope variants, parameter shapes, and mutually exclusive result/error fields before dispatch.
- Preserve notification silence, numeric/string ID identity, continuous input reading, and serialized execution. Parse/invalid-request errors without usable IDs use id: null.
- Malformed input, invalid IDs/methods/params, notification silence, and valid traffic after recoverable errors pass focused wire checks.

## 3. ✅ Make structured results match their wire schemas

[src/mcp/result.ts](../../src/mcp/result.ts) preserves released string envelopes by default. [src/headless/tool-call.ts](../../src/headless/tool-call.ts) supports explicit mcpServer.validateOutputs opt-in so stricter checks do not break existing handlers in a minor.

- Opted-in typed results must match their declared schema without coercion, defaults, or key stripping; malformed results return isError: true. Strings use the typed value instead of the legacy content envelope.
- Keep object-rooted schemas and result wrappers for non-object outputs. Opted-in typed JSON text matches structuredContent. Default output contracts and CLI/REST validation are unchanged.
- Focused checks cover valid scalar/array/object outputs, mismatches, coercion/default rejection, ctx.respond(), default compatibility, and serialization failures.

## 4. ✅ Support cancellation and progress during tools

[src/core/types.ts](../../src/core/types.ts) exposes ctx.mcp.signal and ctx.mcp.reportProgress. Cancellation bypasses the application queue while tool execution remains serialized.

- Handle cancellation outside the application queue, matching the original wire ID. Skip cancelled queued work and expose cooperative cancellation for active handlers and their subprocesses; do not overlap tools while stdout capture is active.
- Expose request-scoped progress using the supplied progress token and the stable transport writer. Stop notifications on completion/cancellation; ignore unknown or completed IDs. Do not promise to interrupt synchronous code or uncooperative child processes.
- Checks pass for queued and active cancellation, abortable child cleanup, string/number ID identity, progress token zero, opt-in, completion suppression, and subsequent calls. Live client cancellation remains unchecked.

## 5. ✅ Expose standard tool annotations

McpToolConfig and tools/list expose title, readOnlyHint, destructiveHint, idempotentHint, and openWorldHint. Definition size measurements include annotations.

- Allow explicit standard annotations per tool, including the built-in resource reader. Use conservative defaults; do not infer safety from command names or the presence of `--yes`.
- Verify `tools/list` metadata and unchanged invocation behavior. Document that hints are advisory, not authorization or a replacement for host confirmation.

## 6. ⬜ Return native MCP content blocks

[src/mcp/result.ts](../../src/mcp/result.ts) only emits text blocks. Images/audio become base64 data inside structured JSON, and handlers cannot return native resource links or embedded resources for clients to render or consume directly.

- Provide an explicit, typed way to return native MCP content while preserving ordinary CLI/HTTP responses. Support image/audio MIME types and resource content without guessing from arbitrary JSON keys.
- Verify native blocks, binary fidelity, mixed text/media, error results, and the ordinary JSON result path under the supported revisions.

## 7. ⬜ Add Streamable HTTP MCP

MCP is stdio-only. [src/http/server.ts](../../src/http/server.ts) serves REST/OpenAPI, not an MCP endpoint. URL-only or remote hosts cannot use argsbarg's MCP server directly. This is an optional expansion, not a stdio conformance failure.

- Add an opt-in MCP endpoint separate from existing REST routes, sharing protocol behavior without sharing mutable client state. Follow the selected protocol revision's HTTP and cancellation rules rather than copying obsolete SSE/session behavior.
- Include origin validation, local-only defaults, authentication/authorization integration, and isolation between callers. Process-global cwd or output capture must not leak between clients.
- Verify a real Streamable HTTP client, request-scoped notifications, cancellation, invalid origin/auth rejection, and unchanged stdio/REST behavior. Do not expose a remote endpoint without these protections.

## 9. ⏸️ Revisit the modern-only architecture

Defer removal of initialization, session state, roots requests, and object-rooted output wrappers to a separate major. Revisit 2026-07-28 discovery, per-request capabilities, required result/cache metadata, and MRTR only once target clients demonstrably support them. Preserve serialized application execution and avoid repeating handler side effects on retries.

## Not Planned

Prompts, resource templates/subscriptions, pagination for small static catalogs, tasks, and MCP Apps are optional expansions, not blockers for the current CLI-to-tools use case. No roots cache/refresh, new lifecycle hooks, settings/session API, or public roots/sampling API.
