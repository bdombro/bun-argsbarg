# Agent skills

> This feature is experimental.

ArgsBarg can generate agent skill directories (`skill.md` + `SKILL.md`) from your CLI schema and install them to `~/.agents/skills/<key>/` per the open standard at https://dotagentsprotocol.com/.

## Enable on the program root

```typescript
export const program = {
  key: "myapp",
  skill: { enabled: true },
  ...
} satisfies CliProgram;
```

When `skill.enabled` is `true`, run `configure install` after `brew install` or `brew upgrade` to install and refresh the skill. When omitted or `enabled` is not `true`, no skill is installed.

The skill directory name is the program `key` with `/`, `\`, and spaces replaced by `_` (e.g. `sqsp-qa`, `full-example`).

## Install via `configure install`

```bash
myapp configure install
```

Skills are installed via `configure install` and removed via `configure uninstall` (run `just install-local` / `just uninstall` in dev).

## Programmatic install

```typescript
import { cliSkillInstall } from "argsbarg/skill/install"; // internal module
```

`cliSkillInstall(root, { global: true, rimraf: true })` returns changed file paths.

## Generated content

- **`skill.md`** — https://dotagentsprotocol.com frontmatter (`id`, `name`, `description`, `enabled`), execution guidance, options & help discovery protocol (`--help`), compact command router, workflow & pitfalls, and client setup
- **`SKILL.md`** — compatibility copy of `skill.md` for tools that expect uppercase filenames

Installed files include an HTML comment hint (`Generated by myapp configure; do not edit.`) after skill frontmatter.

## Client setup

| Client | Skill path |
| --- | --- |
| Cursor, Codex, Copilot, most agents | `~/.agents/skills/<key>/` (auto via `configure install`) |
| Claude Code | Manual symlink to `~/.claude/skills/<key>/` |

```bash
mkdir -p ~/.claude/skills
ln -sf ~/.agents/skills/<key> ~/.claude/skills/<key>
```

Skills describe **shell invocation only** — no MCP setup or `tools/call` guidance. Use **`myapp docs mcp`** (when `docs` and `mcpServer` are enabled) or connect the MCP server for agent execution.

## MCP vs skills vs docs

| Mechanism | Role |
| --- | --- |
| **`myapp mcp`** (requires `mcpServer`) | Runtime tool execution over MCP |
| **`program.skill.enabled`** + **`configure install`** | Persists optimized intent-based skill router at `~/.agents/skills/<key>/` |
| **`myapp docs`** (requires `docs`) | Bundled markdown on stdout (`docs mcp` when MCP enabled) |

`skill.md` is an intent-based router that directs agents to specific subcommands and guides them to use `<subcommand> --help` for JIT option discovery. Prefer `configure install` over `docs skill` for installed agents. See [cli-program.md](cli-program.md).

## Repository skill (`skills/<app>/SKILL.md`)

Running `myapp docs skill --save` writes `skills/<app>/SKILL.md` directly into the consumer repository. Committing this file adheres to the repository skill convention (`skills/<name>/SKILL.md`), allowing agents, tools, and skill managers to discover and install your CLI's skill directly from the source repository.

**Claude Code plugin** (`mcpServer.claudePlugin: true` → `mcp bundle` writes `dist/claude-plugin/<name>.zip`) ships a separate MCP pointer skill (`SKILL.md` only) that routes agents to the bundled MCP server. This is a **dist artifact**, not installed via `configure`.
